# pdfTeX → Rust port: how the code is organised

Goal: a pure-Rust pdfTeX 1.40.29 (TeX Live 2026) with **byte-identical output** to TeX Live's
`pdftex.exe` and **no C dependencies**. Parity is checked by running both engines on the same
inputs and comparing every output file (`tests/difftest.py`).

## Layout

| Path | What |
|---|---|
| `web/` | `pdftex.p` + `pdftex.pool`: TeX Live's pdftex.web with all its change files applied (tie) and tangled to Pascal. Generated by `tools/gen-pascal.sh`; do not edit. |
| `tools/w2rs/` | Python Pascal→Rust translator (`pas.py` parser, `emit.py` emitter, `externs.py` how each web2c/C external maps to Rust). Run `python -I tools/w2rs/emit.py web/pdftex.p engine/src/gen`, then `python -I tools/gen_patches.py` and `python -I tools/gen_fast_macro.py`, from `port/`. |
| `engine/src/gen/` | **Generated** Rust for the whole Pascal program: `globals.rs` (struct `Globals` with every global variable) and `rNN.rs` (`impl Globals` with every Pascal procedure/function as a method, names exactly as in the Pascal, e.g. `self.pdfprint(s)`, `self.pdfbeginobj(i, l)`, `self.printnl(s)`). Never edit by hand; change the translator instead. |
| `engine/src/rt/` | Hand-written ports of everything web2c/pdfTeX implement in C: `texmfmp.rs` (lib/texmfmp.c), `io.rs` (openclose.c, files, input_line), `dump.rs` (format dumping and the format cache), `kpse.rs` (adapter to the kpathsea crate), `pdf/` (pdftexdir/*.c, fonts, images), `synctex.rs`, `fast*.rs` (hand-written fast paths for hot generated routines, see `tools/w2rs/externs.py` FAST_PATHS and `tools/gen_patches.py`), `stubs.rs` (generated stubs for externals no `rt/` file defines; now empty). |
| `crates/` | Standalone pure-Rust ports used by the engine: `zlib` (byte-exact zlib 1.3.2), `pdfread` (xpdf subset), `kpathsea`, `regex` (glibc POSIX regex). |
| `tests/difftest.py` | Differential test harness (see below). |

## The memory model (read this before porting C code)

web2c compiles the Pascal to C where every array is a C array or malloc'ed pointer. The
generated Rust keeps that model exactly:

* Every Pascal array is a `Ptr<T>` field of `Globals` (`rt/ptr.rs`): a copyable raw pointer,
  indexed with the free function `ix(ptr, i) -> &mut T` using the **same indices as the C code**
  (`ix(self.mem, p)`, `ix(self.strpool, k)`, `ix(self.pdfbuf, self.pdfptr)`). `Ptr::off(k)` is
  pointer arithmetic; `Ptr::xmalloc_array(n)` is web2c's `xmallocarray` (n+1 elements);
  `slice(ptr, i, n)` gives a `&mut [T]` view.
* `mem`/`eqtb` words are `MemoryWord` (`rt/words.rs`) with web2c's exact little-endian
  layout and accessors named after the C field path: `.hh_rh()`, `.set_hh_rh(v)`, `.hh_lh()`,
  `.hh_b0()`, `.hh_b1()`, `.int()` (= `.sc`), `.gr()`, `.qqqq_b0()`... `fontinfo` is
  `FMemoryWord`, `hash` is `TwoHalves`.
* C globals of pdftexd.h are the fields of `Globals` with the same (Pascal) names, e.g.
  `self.pdfptr`, `self.pdfbufsize`, `self.fontmax`, `self.pdffontmap` (`Ptr<Ptr<i32>>`),
  `self.pdfcharused` (`Ptr<[u8; 32]>`), `self.strpool`, `self.strstart`, `self.poolptr`.
  Look the exact types up in `engine/src/gen/globals.rs`.
* A C library function `foo(args)` that the Pascal calls becomes a method
  `impl Globals { pub fn foo(&mut self, ...) }` in some `rt/` module; signatures are listed in
  `tools/w2rs/externs.py` (FUNCS/PROCS). `tools/w2rs/stubgen.py` regenerates `rt/stubs.rs`
  with `todo!()` for every external that no `rt/` file defines yet:
  `python -I tools/w2rs/stubgen.py engine/src/gen engine/src/rt > engine/src/rt/stubs.rs`.
* C static state of a module goes into a struct stored in `Runtime` (`rt/mod.rs`, field of
  `Globals` as `self.rt`), e.g. `self.rt.pdfu` (utils.c), `self.rt.fonts`.
* TeX strings: `self.tex_string(s) -> Vec<u8>`; `self.maketexstring_u(bytes)` (utils.c
  maketexstring); messages via `self.pdftex_warn(&str)` / `self.pdftex_fail(&str) -> !`
  (utils.c, same output format); `self.tex_printf(&str)`; PDF output via
  `self.pdf_puts(&[u8])`, `self.pdf_printf(&str)`, `self.pdfout(byte)`, `self.pdfroom(n)` and
  the generated Pascal procedures (`pdfprintint`, `pdfbeginobj`, ...).
* File lookup: `self.rt.kpse().find_file(name, kpse::TFM_FORMAT, must_exist)` (format
  numbers in `rt/kpse.rs`, same as kpathsea's enum). Opening files the way TeX does:
  set `nameoffile` and call `open_input(fmt)`.
* C `printf` formats must be reproduced exactly (`%g`, `%.Nf`, `%i` of negative values cast to
  unsigned, truncation at buffer sizes like PRINTF_BUF_SIZE=1024).

## Building and testing

```bash
cd port/engine && cargo build            # debug: null-pointer checks in ix(), backtraces
cargo build --release                    # release: LTO, used for speed measurements
python -I port/tests/difftest.py NAME --files tests/cases/x.tex -- ARGS... [-- ARGS2...]
```
`difftest.py` copies the input files into `port/test/NAME/c` (TeX Live pdftex) and
`port/test/NAME/r` (Rust), runs each `--` step in both, and compares stdout/stderr and every
file byte for byte (formats after gunzip). It sets `SOURCE_DATE_EPOCH=1700000000`,
`FORCE_SOURCE_DATE=1` and `TEXRS_SELFAUTOLOC` (makes the Rust binary behave as if it lived in
TeX Live's `bin/windows`, so it finds texmf.cnf and the TeX tree). Example (plain format, then
a document): `difftest.py t --files tests/cases/plain1.tex -- -ini -interaction=batchmode
-translate-file=cp227.tcx plain \dump -- -fmt=plain -interaction=nonstopmode plain1`.

TeX Live's pdftex is `tools/texlive/2026/bin/windows/pdftex.exe` (or `$TEXRS_TEXLIVE/bin/windows`);
its C sources are in [texlive-source](https://github.com/TeX-Live/texlive-source) (branch2026) under
`texk/web2c` (pdftexdir/, lib/, synctexdir/) and `libs`.
